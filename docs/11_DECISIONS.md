# 设计决策记录

## ADR-001：选择 Web/PWA，而不是 EXE 或原生 App

**状态：已采用**

同一套代码需要同时覆盖 Windows、iPad 和手机。Web/PWA 可用一个网址交付，维护成本最低；EXE 无法在手机使用，原生 App 需要分别开发和上架。

## ADR-002：采用原生 JavaScript

**状态：已采用**

项目功能规模可控，原生技术无需构建工具，Cloudflare 可直接上传 ZIP。代价是业务文件较长，未来可按模块拆分。

## ADR-003：题库静态打包，不放数据库

**状态：已采用**

题库只读且体积约 300KB，随站点缓存能获得最快启动和最佳离线体验。数据库只保存用户状态，降低费用和权限复杂度。

## ADR-004：LocalStorage 本地优先

**状态：已采用**

用户的关键场景是地铁和不稳定网络。每次作答先本地写入，再异步云同步，保证网络失败不阻塞答题。

## ADR-005：Supabase JSONB 单行进度

**状态：已采用，有已知限制**

个人项目优先简单可靠，整份 JSON upsert 容易理解和迁移。代价是多设备离线并发合并不如事件表精确。

## ADR-006：首次 Magic Link + 后续同步密码，而非 6 位验证码

**状态：已采用**

Supabase 新版界面要求自定义 SMTP 才能修改默认邮件模板。为保持免费和低配置，首次认证使用默认 `Sign in` 邮件链接；考虑到 iOS Safari 与主屏幕网页 App 可能不共享会话，认证后允许设置题库专用同步密码，其他设备可直接登录。

## ADR-007：Cloudflare Workers + Supabase 免费方案

**状态：已采用**

免费、自动 HTTPS、无需服务器运维。代价是中国大陆网络访问可能不稳定。

## ADR-008：资源查询版本 + 网络优先缓存

**状态：已采用**

早期 Cache First 导致新 HTML 和旧 JS 混用。现在每次版本统一增加 `?v=N`，Service Worker 联网时优先获取新资源，离线才使用缓存。
